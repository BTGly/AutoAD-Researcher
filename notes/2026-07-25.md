## 本地路径 intake 与资料任务链路

- 目标：修复用户同时提供本地仓库、数据集等路径时只生成研究摘要、没有独立 Source/资料 Job/任务草案的问题；保持既有来源动作、实验执行和报告链路不变。
- 设计：复用现有 Decision、DialogueGate、Material Inspection Loop、Source registry 和 Pipeline Job 控制面。`local_path_sources` 是主字段，旧的 `local_path_source` 仅作兼容；每个路径独立检查、登记、排队并写入 action receipt，用户描述只作为提示，不作为类型事实。
- 本地资料：结构检查增加图像文件证据、递归深度和总扫描上限，MVTec 这类嵌套图像目录可映射为 dataset；每个 dataset 额外排队 `dataset_manifest` Job，Worker 生成独立 manifest。仓库仍走现有 acquire/summarize，混合目录仍保留通用 local_path 视图。
- 任务状态：资料部分成功时不丢弃其他 Source；有失败资料时仍可保存 `blocked_by_materials` 的 plan-only 任务草案，但确认接口明确拒绝，避免把“草案已保存”误报为可执行任务。
- 回复与 API：回复和 `ChatResponse` 暴露 receipt 驱动的资料状态；只有真实回执才能声明登记或 Job 排队，失败路径保留具体阻塞原因。

## 后台任务与主对话同步闭环

- 目标：让研究者提交的本地仓库、数据集等资料立即成为正式 Source 和可见 Pipeline Job；后台处理期间仍可继续对话；完成或失败结果以可恢复的助手消息进入主聊天和后续上下文。
- 实现：本地路径先保留受限只读会话检查，再以实际目录检查结果 promote 为 Source，并用稳定 idempotency key 创建仓库 acquire/summarize 或 dataset manifest Job；重复提交复用已有 Source/Job。
- 对话与事件：新增共享、带锁的 `chat/transcript.jsonl` store，HTTP chat 和 worker 均使用它；worker 在关键 Job 终态生成一次 `task_result` 或 `task_failure` 结构化助手消息，写入 `conversation.message.created` 事件。中间 acquisition Job 仅更新右侧任务卡，避免主聊天刷屏。
- 前端：WebSocket 收到持久对话事件后按 `message_id` 去重插入主聊天；刷新和任务切换从 transcript 恢复任务卡。Sources/Jobs/Evidence 仍复用现有 sidebar，任务消息显示关联 Job、产物和失败摘要。
- 上下文：持久 transcript 优先于浏览器传入的旧尾部；context builder 纳入 recent task messages，但失败消息不会被视为可用证据或科学结论。
- 验证：定向 Python 回归 `38 passed`，接口/事件回归 `11 passed`，前端 `npm run build` 通过；完整项目门禁待本条日志写入后执行。
